# Пакет 05 · Тесты

**Цель:** научиться писать тесты, которые ловят регрессии, а не мешают рефакторить.

**Ветка:** `packet/05-tests` · **Время:** 6–8 ч

## Теория (2 ч)

- Пирамида: unit (много, быстрые) → integration → e2e (мало, медленные).
- `@nestjs/testing`, `Test.createTestingModule`, `overrideProvider`.
- `supertest` для HTTP, отдельная тестовая БД, очистка между тестами.

## Задачи

- [ ] 1. **Тестовая БД**: `docker compose` сервис `db-test` на порту 5434 или отдельная схема; `DATABASE_URL_TEST` в `.env.test`; `prisma migrate deploy` в `beforeAll`.
- [ ] 2. **e2e** `test/vacancies.e2e-spec.ts`: создание → список → получение по id → 404 на чужой id → удаление → 404 повторно.
- [ ] 3. **e2e на валидацию**: `POST` с пустым `title` → 400 и структура ошибки.
- [ ] 4. **Изоляция тестов**: `TRUNCATE ... RESTART IDENTITY CASCADE` в `beforeEach`, а не «надейся, что порядок правильный».
- [ ] 5. **Скрипт** `npm run test:e2e` в CI (пока можно пропустить, если нет сервиса).

## Критерии приёмки

- [ ] `npm test` и `npm run test:e2e` зелёные на чистой машине
- [ ] Тесты не зависят от порядка запуска
- [ ] Нет `sleep` в тестах
- [ ] Покрыты и успешные, и ошибочные сценарии

## Вопросы, на которые умеешь отвечать

- Как тестировать код с `Date.now()` и случайностью?
- Что такое flaky-тест и как с ним бороться?
