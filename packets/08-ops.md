# Пакет 08 · Эксплуатация

**Цель:** сервис должен запускаться одной командой, падать предсказуемо и оставлять
после себя читаемые логи.

**Ветка:** `packet/08-ops` · **Время:** 6–8 ч

## Теория (2 ч)

- 12-factor: конфиг из окружения, логи в stdout, stateless-процесс.
- Graceful shutdown: перестать принимать запросы → дождаться текущих → закрыть пул.
- Многостадийная сборка: `builder` + `runner`, `node:22-alpine`, непривилегированный пользователь.

## Задачи

- [ ] 1. **Валидация конфига** при старте (`@nestjs/config` + схема): нет `DATABASE_URL` → падение с понятным сообщением, а не 500 на первом запросе.
- [ ] 2. **`pino`** вместо `console.log`: JSON-логи, `requestId` через `AsyncLocalStorage`.
- [ ] 3. **`app.enableShutdownHooks()`** + `SIGTERM`-обработчик, закрытие Prisma.
- [ ] 4. **`Dockerfile`** multi-stage, `USER node`, `HEALTHCHECK` на `/api/health`.
- [ ] 5. Сервис `api` в `docker-compose` с `depends_on: db: condition: service_healthy`.
- [ ] 6. `npm run start:prod` из собранного образа — работает без `node_modules` на хосте.

## Критерии приёмки

- [ ] `docker compose up --build` поднимает API и БД с нуля одной командой
- [ ] `docker stop` завершает процесс без обрыва соединений с БД
- [ ] В логах нет секретов и паролей от БД
- [ ] Образ меньше 300 МБ

## Вопросы, на которые умеешь отвечать

- Что произойдёт с запросами в момент `SIGTERM` без graceful shutdown?
- Почему конфиг через env, а не через файл в репозитории?
