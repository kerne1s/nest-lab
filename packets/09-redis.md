# Пакет 09 · Redis и очереди

**Цель:** добавить кэш и фоновые задачи — то, что в вакансиях встречается чаще всего
после «NestJS + PostgreSQL».

**Ветка:** `packet/09-redis` · **Время:** 8–10 ч

## Теория (2–3 ч)

- Redis: строки, хеши, TTL, `SCAN`, атомарность (`INCR`, `SET NX`).
- Инвалидация кэша: по TTL, по ключу, по тегу — и почему «кэш + БД» всегда про компромисс.
- BullMQ: очередь, воркер, retry с backoff, идемпотентность джобы.

## Задачи

- [ ] 1. **Сервис `redis`** в `docker-compose`, клиент `ioredis` как провайдер.
- [ ] 2. **Кэш списка вакансий**: ключ по хешу query-параметров, TTL 60 с, инвалидация на `POST/DELETE`.
- [ ] 3. **Очередь `refresh-vacancies`**: воркер, который тянет данные и пишет в БД; ручной триггер `POST /admin/jobs/refresh`.
- [ ] 4. **Retry + dead letter**: упавшая джоба не теряется, после 3 попыток уходит в failed.
- [ ] 5. **Замер**: время `GET /vacancies` с кэшем и без (на 100k строк).

## Критерии приёмки

- [ ] После `POST /vacancies` список отдаёт свежие данные (инвалидация работает)
- [ ] Падение воркера не ломает API
- [ ] Джоба идемпотентна: повторный запуск не создаёт дублей (за счёт `upsert` по `url`)
- [ ] Цифры до/после в заметках
