# Пакеты задач

Один пакет = одна тема = одна ветка = одно ревью. Пакет считается сданным, когда
зелёные тесты, пройден чеклист приёмки и ответы на «вопросы» пакета не вызывают
затруднений.

## Как работаем

1. Берёшь пакет из списка ниже, создаёшь ветку: `git switch -c packet/01-filters`.
2. Делаешь задачи, коммитишь по одной: `feat(vacancies): фильтр по минимальной зарплате`.
3. Пушишь ветку и присылаешь ссылку (или просто говоришь «пакет 01 готов» — я смотрю
   локальный дифф `git diff main...packet/01-filters`).
4. Я ревью: корректность, идиоматичность NestJS, SQL и индексы, тесты, обработка
   ошибок, безопасность. Замечания — списком, с указанием файла и строки.
5. Правишь, мержим в `main`, переходишь к следующему пакету.

Правила простые: **один пакет — одна ветка**, `main` всегда зелёный, коммиты в
[Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/)
(`feat:`, `fix:`, `test:`, `refactor:`, `docs:`, `chore:`).

## Definition of Done для любого пакета

- [ ] `npm run build` проходит без ошибок и без `any`
- [ ] `npm test` зелёный, на новую логику есть хотя бы один тест
- [ ] Swagger (`/docs`) отражает новые эндпоинты и DTO
- [ ] Чеклист приёмки пакета закрыт
- [ ] В PR-описании: что сделано, что проверил, что осталось

## Про GitHub

Локальный репозиторий уже инициализирован, `main` содержит стартовый скелет.
Чтобы вынести на GitHub (нужно для CI, портфолио и ссылки в резюме):

```bash
# 1. Создай пустой репозиторий на github.com (без README и .gitignore)
# 2. Привяжи remote и запушь
git remote add origin git@github.com:kerne1s/nest-lab.git
git push -u origin main
```

`.github/workflows/ci.yml` уже лежит в репозитории: после пуша GitHub Actions
начнёт гонять `build` и `test` на каждый push и PR. Пушу я не могу — нет доступа
к твоим credentials, поэтому пушит и открывает PR-ы человек. Ревью я делаю по
локальной ветке, содержимое от этого не меняется.

Публичный репозиторий имеет смысл держать **без** `.env` и без реальных данных —
`.gitignore` это уже закрывает.
